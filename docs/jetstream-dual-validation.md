## 功能与数据验证

- 先部署旧版 `5d45a4c`，通过真实评论保存、后台 CPU 推理和展示，再升级双模型。
- 集成实现 `96303ca`；连接复用与云端资源配置 `7abc083`。
- 每条评论分别拥有情绪和三分类结果、状态、任务租约、最多三次自动尝试及独立手动重试。一套失败不影响另一套已完成输出。
- 迁移为已有评论补充三分类；升级前分析 ID 与全部 28 项原始得分哈希保持不变。
- 看板显示全站非性能流量的三分类数量/占比与阈值情绪计数；支持点击分布筛选、三分类结果与状态筛选、收藏及处理。统计说明明确“一条评论可有多个情绪标签”；分布统计不随列表筛选改变。
- 本地及云端独立 PostgreSQL 测试库均通过 **13 项测试**。覆盖双模型独立结果、过滤统计、失败保留/重试、并发领取、中断恢复、原始输出不可覆盖及就绪检查。
- PostgreSQL 和两套队列 worker 重启前后，13 张业务表的行数和内容校验完全一致。心跳运行表排除在静态校验之外。
- 浏览器公网实际发布负面/中性评论，核对双结果、分布、负面筛选、收藏与已处理。测试评论均为明确的演示文本。
- 升级前数据库备份保存在服务器 `/home/exouser/sentiment-analysis-backups/before-dual-model.dump`；密钥、密码、会话原值和数据库备份不进入仓库。

## 线程选择

固定四条英文校园短评各重复十次，batch 1、8 次额外预热；分别测试 1/2/4/6/8 线程。三分类 Engine 另有启动 20 次预热。使用原权重，不训练、不微调、不修改分类阈值。矩阵只用于部署性能选择，不能作为分类准确率评测。

| 模型 | 线程 | p50（ms） | p95（ms） | 吞吐量（条/s） |
| --- | ---: | ---: | ---: | ---: |
| emotion | 1 | 22.44 | 28.78 | 43.18 |
| emotion | 2 | 14.55 | 18.37 | 66.18 |
| emotion | 4 | 9.42 | 11.71 | 102.60 |
| emotion | 6 | 8.25 | 9.76 | 119.34 |
| emotion | 8 | 14.57 | 18.80 | 67.67 |
| sentiment | 1 | 62.14 | 77.48 | 15.56 |
| sentiment | 2 | 70.59 | 86.30 | 13.71 |
| sentiment | 4 | 35.00 | 40.24 | 28.05 |
| sentiment | 6 | 44.84 | 47.31 | 22.47 |
| sentiment | 8 | 45.45 | 78.82 | 20.02 |

**采用情绪 6 线程、三分类 4 线程，inter-op 均为 1。** 多线程存在调度和内存开销，8 线程没有带来更好的短评延迟。不通过空转或重复加载模型制造 CPU 占用。两套模型各常驻一份，后台独立并行；API、数据库分别允许 2 CPU，模型容器分别允许 6 CPU，CPU 上限不是独占预留，推理线程合计约 10，为服务留出余量。

云端用 `.env` 中 `COMPOSE_FILE=compose.yaml:compose.jetstream.yaml` 复现资源预算。API 与两个 worker 分别使用上限 8 的连接池；单例锁使用独立专用连接。

缓存启动记录：情绪模型加载 414.12 ms、预热前首次推理 15.24 ms；三分类加载 4946.97 ms、预热前首次推理 28.19 ms。两者加载定义不同：三分类包含 Torch/Transformers 导入；下载与校验另计，不能直接比较加载数字。

## 双模型端到端性能

最终使用独立客户端容器，通过真实 HTTP 评论接口写 PostgreSQL，等待**两套分析均完成**。每阶段固定四条校园短评循环 100 次，先预热 8 条；batch 1，线程 6/4；性能活动不进入用户页、看板或分类成绩。测试时没有其他主动交互流量。

服务端完成时间从评论在数据库创建到最后一套分析提交，包含真实后台排队。客户端观察还包含 HTTP 和 15 ms 轮询误差；客户端位于同一 Docker 网络，**不包含学生到 Jetstream2 的公网网络延迟**。一次 100 样本阶段不足以预测长期容量；并发更高不一定带来更高吞吐量。不同阶段推理延迟有调度/缓存波动，不把离线线程扫描和完整产品基准混为同一测试。

## 官方分类成绩

新实例情绪模型已完成固定 GoEmotions simplified/test 全部 5,427 条：Micro-F1 **58.83%**、Macro-F1 **45.16%**、Exact-match **47.89%**（整组 28 标签完全匹配）。全部类别指标保存于 emotion-metrics.json，没有删除低分类别。

运行 ID `b0a105a6-3a89-4c26-a043-c71a15b2c17f`。逐条预测保存在服务器持久报告卷，并可从平台评测页下载；SHA-256 `38ae78028d05a0167ee3cb2c42e491d7968943491e126326186c5db747623c77`。独立 rescore 与原指标一致。评测不影响阈值，现场评论和人工纠正不混入测试成绩。

三分类完整官方测试仍引用之前本地 12,284 条的独立结果（Accuracy 72.18%、Macro-F1 72.40%、Macro-Recall 73.49%），**本轮没有在云端重复完整三分类质量测试**；云端新测的是功能与性能。两套模型与数据 revision、许可证和限制分别见 [原情绪来源](sources.json) 与 [三分类验证](cardiff-cpu-validation.md)。TweetEval 原始数据条款核查仍待完成，仓库不打包原始推文。

## 运行和复现

```sh
# 已在服务器 /home/exouser/sentiment-analysis 中配置 .env
docker compose up -d --build
docker compose ps
docker compose --profile tools run --rm tests
# 在独立客户端执行最终基准，不在 API 容器中争用 CPU
docker compose --profile tools run --rm --no-deps -T cli python - \
  --base http://web --samples 100 --output /reports/jetstream-dual-benchmark.json \
  < scripts/benchmark_dual.py
# 情绪官方评测
docker compose --profile tools run --rm cli python -m app.cli evaluate
```

演示：输入任意展示名 → 发现活动 → 发布英文评论 → 同条评论查看两套结果 → 分析看板查看分布 → 点击负面筛选 → 收藏 → 标记已处理 → 评测报告。

完整原始记录位于 [docs/results/jetstream-dual](results/jetstream-dual)。公开演示沿用已确认的无密码身份方式。
